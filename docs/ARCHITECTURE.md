# Architecture

Status: **current**

## Interfaces
| Interface | Entry | For |
|---|---|---|
| Desktop app | `python -m cctv_analysis.app` / `CCTVAnalysis.exe` | non-technical users (shops, malls, security staff) |
| Colab notebook | `cctv-analysis.ipynb` (generated by `tools/build_notebook.py` from the package) | Google Drive users with a free GPU |
| CLI | `python -m cctv_analysis --input … --output … [--preset fast] [--retime] [--reports-only] key=value…` | scripted / scheduled runs |
| Python | `from cctv_analysis.pipeline import Analyzer; Analyzer(Config(...), progress, cancel).run()` | developers |
All four use the same `Config` (`config.py`, one field = one meaning, validated by `Config.validate()`).

## Pipeline
```
find_videos (natural order, folder keywords, globs)
  → _select: skip finished (path+size+mtime) and duplicate content (quick hash)
  → plan: probe + recording time for every video (timeline.resolve_start_time) → chronological order
  → per video: scan_motion (MOG2 + frame diff on a small grey stream; OSD mask; lighting/tamper)
       → per event: event_clock (re-read DVR clock) → YOLO track (+pose) → faces (YuNet, SFace,
         identities, watchlist) → plates (best vehicle frames at full resolution) → counting lines
         → snapshots / contact sheet → SigLIP-2 tags → VLM description → rules.score_event → clip
  → reports: reels (per day), all-time + weekly Excel, Unique_Faces.xlsx, HTML, charts
```
Cancellation is checked between videos, between events and every 25 frames. A video whose events
all fail is marked `error`; the same error on 3 videos in a row stops the run.

|---|---|

## Cases
A case runs the pipeline once per seized source, each into `<case>/sources/<id>/` (an ordinary
output folder), so per-source views, reports and exports are unchanged; `journey.py` and `reid.py`
query across those folders on calibrated time. Layout and rules: `docs/CASES.md`.

## Storage
`<output>/analysis.db` (SQLite) is the source of truth for analysis results, written by the
analyzer only (working copy in `work_dir`, copied over after each video). Tables: `videos`,
`events`, `tracks`, `faces`, `detections`, `plates`, `tamper`, `reel_segments`, `face_alerts`,
`file_hashes`, `runs`; columns added by later versions are migrated on open
(`Store._ADDED`). Indexes on the app's query paths (`events(start_dt)`, `events(camera,start_dt)`,
`tracks(identity)`, `plates(text)`, …). Reviews: `<output>/reviews.db`. Identities:
`identities.json/.npy`. Search index: `semantic_index.npz`.
